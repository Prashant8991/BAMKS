2. Base Paper Details

Title: Blockchain-assisted attribute-based multi-keyword search for dynamic encrypted data in cloud-edge-IoT

Authors: Hanlei Cheng, Sio-Long Lo, Jing Lu

Published In: Internet of Things, Elsevier (ScienceDirect), Volume 36, Article 101838

Publication Date: Accepted 29 November 2025; Available online 6 December 2025

DOI: https://doi.org/10.1016/j.iot.2025.101838

3. Summary of the Selected Research Paper

The selected paper addresses the problem of retrieving specific documents from a large pool of encrypted data that has been outsourced to third-party cloud and edge servers. In real deployments such as electronic health record systems, several organisations jointly own and continuously update files, and authorised users need to locate relevant files using keywords without exposing the file content, the search query, or the identity of the searcher to the storage provider.

To solve this, the authors propose a scheme named BAMKS (Blockchain-assisted Attribute-based Multi-Keyword Search). The system allows several data owners to jointly protect a shared decryption token using attribute-based encryption, so that only users whose attributes satisfy a defined access policy can eventually decrypt the outsourced files. Each file is also associated with an encrypted keyword index, allowing a user to build a single search request (a trapdoor) covering multiple keywords at once, rather than searching one keyword at a time.

A blockchain layer is used to store the encrypted indexes and to run smart contracts that verify whether the cloud server has returned the complete and correct set of matching files, using an aggregated zero-knowledge proof. The scheme additionally supports revoking a user's or an attribute's access, and identifying a user who has leaked their private key, without needing to re-encrypt every file already stored on the server. The authors formally prove the scheme resists chosen-plaintext and chosen-keyword attacks, and their experiments show it is faster and more storage-efficient than several recent comparable schemes.

4. Research Gap / Limitations of Existing Work

Although BAMKS supports data that changes over time, its mechanism for handling change operates only at the level of an entire file collection, which the authors call a ‘version’. Whenever any single file needs to be added, removed, or modified, the scheme requires that the master keys for the whole version be refreshed and that the encrypted keyword index for every file and every keyword in that version be regenerated, even for files that were never touched by the update.

The authors explicitly acknowledge this shortfall in their concluding remarks, stating that extending the scheme to support continuous, file-level insertion and deletion operations is left for future work. In other words, the scheme currently has no defined procedure for updating, inserting, or removing a single file's entry independently of the rest of the collection.

No file-level granularity: any single change forces a full-version index rebuild.

Update cost grows with the size of the entire file collection, not with the size of the change.

No dedicated delete or insert operation is defined in the formal algorithm set (Section 4.3 of the base paper lists twenty algorithms, none of which perform a single-file insert or delete).

This limits practicality in scenarios where files are added or removed frequently, such as continuous IoT sensor logging or streaming health records.

5. Problem Statement

Given a blockchain-assisted, attribute-based multi-keyword searchable encryption system in which data owners periodically add, remove, or modify individual files within a shared, dynamically evolving file collection, design a mechanism that updates the encrypted keyword index for only the affected file, while preserving the correctness of keyword search, the confidentiality guarantees, and the verifiability of search results for all other unaffected files in the collection.

6. Proposed Contribution

We propose an incremental index update mechanism, referred to as BAMKS-D (Dynamic), which extends the update procedure of the base scheme to operate at the granularity of a single file rather than an entire version. Three operations are introduced:

Insert: when a new file is added, index entries are generated only for that file's keywords and appended to the existing encrypted index, leaving all other entries untouched.

Delete: when a file is removed, only its corresponding index entries are deleted from the encrypted index.

Modify: implemented as a delete of the file's existing entries followed by an insert of its updated entries.

The base scheme's original full-rebuild update procedure is also implemented, so that it can serve as a direct performance baseline. Both mechanisms are evaluated on an identical dataset and search interface, allowing a controlled, like-for-like comparison of update cost, index size growth, and search correctness after updates — which the base paper does not provide, since it evaluates only the full-rebuild update strategy.

Both the baseline and proposed update paths will be implemented over a common encryption and search core (symmetric file encryption together with a keyed-hash-based keyword index), so that the comparison isolates the effect of the update strategy itself rather than differences in the surrounding cryptographic machinery.

8. Evaluation Metrics

Update time and index size will be measured as the number of files in the collection and the number of update operations increase, in order to demonstrate how the proposed incremental approach scales more favourably than the baseline full-rebuild approach as the dataset grows. Search correctness will be verified by confirming that a query for a given keyword returns exactly the expected set of files before and after each update operation.
